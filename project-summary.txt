EXTRA BACKEND FEATURE

I added a bulk delete feature that allows an authenticated user to delete multiple tasks in one request.

Bulk Delete Endpoint

Method:
DELETE

Path:
/api/tasks/bulk

Authentication:
Required. The user must be logged in.

Query Parameters:
None

Request Body:

{
  "ids": [1, 2, 3]
}

Behavior:

- Accepts an array of task IDs.
- Requires the ids array to contain at least one item.
- Validates that task IDs are valid numbers.
- Deletes multiple tasks in one request.
- Uses Prisma deleteMany with an "in" filter.
- Only deletes tasks that belong to the currently authenticated user.
- Prevents users from deleting tasks that belong to another user.

Example Request:

DELETE /api/tasks/bulk

Request Body:

{
  "ids": [1, 2, 3]
}

Success Response Example:

{
  "message": "Tasks deleted successfully",
  "deletedCount": 2
}


TASK RETRIEVAL

Method:
GET

Path:
/api/tasks

Authentication:
Required.

The GET /api/tasks endpoint supports pagination, searching, and sorting.

Supported Query Parameters:

page
Used to select the requested page.

Example:

GET /api/tasks?page=1


limit
Controls the number of tasks returned per page.

Example:

GET /api/tasks?page=1&limit=10


find
Searches tasks by title.

Example:

GET /api/tasks?find=meeting


sortBy
Selects the field used for sorting.

Supported values include:

- title
- isCompleted
- priority
- createdAt

Example:

GET /api/tasks?sortBy=createdAt


sortDirection
Controls the sorting direction.

Supported values:

- asc
- desc

Example:

GET /api/tasks?sortBy=createdAt&sortDirection=desc


Combined Example:

GET /api/tasks?page=1&limit=10&find=meeting&sortBy=createdAt&sortDirection=desc


CREATE TASK

Method:
POST

Path:
/api/tasks

Authentication:
Required.

Example Request Body:

{
  "title": "Finish final project",
  "isCompleted": false
}

Behavior:

- Creates a new task for the authenticated user.
- The created task belongs to that user.
- Task input is validated before it is saved.


GET ONE TASK

Method:
GET

Path:
/api/tasks/:id

Authentication:
Required.

Example:

GET /api/tasks/15

Behavior:

- Retrieves one task by ID.
- Users can only retrieve tasks that belong to them.


UPDATE TASK

Method:
PATCH

Path:
/api/tasks/:id

Authentication:
Required.

Example Request:

PATCH /api/tasks/15

Example Request Body:

{
  "title": "Update final project",
  "isCompleted": true
}

Behavior:

- Updates an existing task.
- Users can only update tasks that belong to them.
- Updated task input is validated before it is saved.


DELETE ONE TASK

Method:
DELETE

Path:
/api/tasks/:id

Authentication:
Required.

Example:

DELETE /api/tasks/15

Behavior:

- Deletes one task.
- Users can only delete their own tasks.


AUTHENTICATION

User Registration

Method:
POST

Path:
/api/users/register


User Logon

Method:
POST

Path:
/api/users/logon


User Logoff

Method:
POST

Path:
/api/users/logoff


Authentication is implemented using JWT.

Authenticated task requests use the logged-in user's ID so users can only work with their own tasks.


SECURITY

The application includes:

- JWT authentication
- HttpOnly authentication cookies
- CSRF protection
- Password hashing
- XSS sanitization
- Helmet security headers
- Rate limiting
- Input validation
- User ownership checks

Users can only access, update, or delete their own tasks.

The bulk delete feature also checks user ownership so one user cannot delete tasks belonging to another user.
